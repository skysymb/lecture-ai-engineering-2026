## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした。
    - LLM の API は前のやり取りを覚えていないので、ユーザーの発言とモデルの返答を `types.Content` のリスト（`Conversation.history`）に貯め、毎回「これまでの履歴＋今回の質問」をまとめて `contents` に渡す。
    - API 呼び出しが成功したときだけ履歴に追加する。失敗したターン（429 など）の質問は履歴に残さず、会話は続けられる。
    - 400/401/403/404（キーやモデル名の問題）は続けても直らないので終了する。
    - `exit` / `quit` / 空行 / Ctrl-D で終了。
  - 従来どおり `uv run python -m app.ask "質問"` で1回だけ質問することもできる。
  - `tests/test_ask.py` を追加した。APIキーなしで動く偽のクライアントを使い、次を確認している。
    - 2回目の呼び出しに1回目の質問と返答が含まれること
    - 失敗したターンが履歴に残らないこと
    - トークン数の表示形式
- 結果：
  - `uv run pytest -q` で全テスト（既存11件＋追加5件）が通った。
  - 実際の Gemini API での動作確認は、下の環境の問題によりできていない。
- 気づき・疑問：
  - 履歴を毎回すべて送るので、ターンを重ねるほど入力トークン数が増える。無料枠のトークン上限や料金に効いてくるはずで、長い会話では古い履歴を要約したり捨てたりする工夫が必要そう。
  - google-genai には `client.chats.create()` で履歴を管理してくれる仕組みもあるが、「API はステートレスで、履歴はクライアント側が送り直している」ことを理解するために、あえて自分でリストを管理した。

## 環境の問題（Gemini API が使えなかった）

- 症状：`uv run python -m app.ask` を実行すると `APIキーかモデル名に問題があります（403）: Your project has been denied access. Please contact support.` と表示される。
- AI Studio ではプロジェクトの Billing tier が「Free tier unavailable」と表示されていた。
- キー自体は Codespaces に渡っており Google まで届いているので、キーやコードではなく、Google 側でプロジェクト（アカウント）の無料枠が使えない状態と判断した。
- 試したこと：
  - エラーの原因を Claude に相談しながら調べた（キーの読み込みは正常で、Google 側でプロジェクトの無料枠が使えない状態と判断）
  - AI Studio で「Free tier unavailable」と表示され、無料枠では利用できなかった
  - 解消するには支払い情報（クレジットカード）の登録が必要そうだったため、今回は見送り、API を使わずに検証できる実装レベルに取り組んだ
